### **문제 설명**

프로그래머스 팀에서는 기능 개선 작업을 수행 중입니다. 각 기능은 진도가 100%일 때 서비스에 반영할 수 있습니다.

또, 각 기능의 개발속도는 모두 다르기 때문에 뒤에 있는 기능이 앞에 있는 기능보다 먼저 개발될 수 있고, 이때 뒤에 있는 기능은 앞에 있는 기능이 배포될 때 함께 배포됩니다.

먼저 배포되어야 하는 순서대로 작업의 진도가 적힌 정수 배열 progresses와 각 작업의 개발 속도가 적힌 정수 배열 speeds가 주어질 때 각 배포마다 몇 개의 기능이 배포되는지를 return 하도록 solution 함수를 완성하세요.

### 제한 사항

- 작업의 개수(progresses, speeds배열의 길이)는 100개 이하입니다.
- 작업 진도는 100 미만의 자연수입니다.
- 작업 속도는 100 이하의 자연수입니다.
- 배포는 하루에 한 번만 할 수 있으며, 하루의 끝에 이루어진다고 가정합니다. 예를 들어 진도율이 95%인 작업의 개발 속도가 하루에 4%라면 배포는 2일 뒤에 이루어집니다.

### 입출력 예

| progresses               | speeds             | return    |
| ------------------------ | ------------------ | --------- |
| [93, 30, 55]             | [1, 30, 5]         | [2, 1]    |
| [95, 90, 99, 99, 80, 99] | [1, 1, 1, 1, 1, 1] | [1, 3, 2] |

<hr/>

### 1단계: 각 기능의 완료까지 남은 일수 계산하기

| 기능 번호 | 진행률 | 속도 | 남은 일수 = 올림((100 - 진행률) / 속도) |
| --------- | ------ | ---- | --------------------------------------- |
| 1번       | 93     | 1    | (100 - 93) / 1 = 7                      |
| 2번       | 30     | 30   | (100 - 30) / 30 = 2.33 → 올림 3         |
| 3번       | 55     | 5    | (100 - 55) / 5 = 9                      |

`→ days = [7, 3, 9]`

### !!2단계: 배포 그룹 나누기

| i   | days\[i] | currentDay | 조건: days\[i] <= currentDay? | count | result | 설명                                             |
| --- | -------- | ---------- | ----------------------------- | ----- | ------ | ------------------------------------------------ |
| 0   | 7        | 7          | —                             | 1     | \[]    | 첫 작업 기준일 설정                              |
| 1   | 3        | 7          | 3 <= 7 → 참                   | 2     | \[]    | 2번째 작업이 더 빨리 끝나서 첫 그룹에 포함       |
| 2   | 9        | 7          | 9 <= 7 → 거짓                 | 1     | \[2]   | 9일 걸리므로 이전 그룹 배포(2개) 후 새 그룹 시작 |

### !!3단계: 반복 종료 후 마지막 그룹 추가

마지막 그룹은 count = 1 (3번째 작업 혼자 배포)
`→ result = [2, 1]`

- 1번째와 2번째 기능은 7일째 같이 배포
- 3번째 기능은 9일째 혼자 배포

```js
function solution(progresses, speeds) {
  // 남은 일수 배열
  const days = []

  // (100 - 현재 진행률) / 속도 → 올림 처리
  for (let i = 0; i < progresses.length; i++) {
    const remainDay = Math.ceil(100 - progresses[i] / speeds[i])
    days.push(remainDay)
  }

  const result = []
  let currentDay = days[0]
  let count = 1

  for (let i = 1; i < days.length; i++) {
    if (days[i] <= currentDay) {
      // 현재 작업이 기준일보다 빠르거나 같으면 함께 배포
      count++
    } else {
      // 늦으면 지금까지 센 배포 개수 저장 후 새 그룹 시작
      result.push(count)
      currentDay = days[i]
      count = 1
    }
  }

  result.push(count)

  return result
}
```

- result.push(count) 지금까지 센 배포 개수 저장 (기존 그룹 완성)
- currentDay = days[i] 새 그룹 기준 완료일을 갱신
- count = 1 새 그룹 첫 작업이니까 count 초기화
